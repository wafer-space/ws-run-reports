  WAFER.SPACE RUN 1 — STANDARD CELL & SRAM DENSITY REPORT
  GF180MCU Process (GlobalFoundries 180nm), Shuttle G801
============================================================================


INTRODUCTION
============

This report analyzes the standard cell and SRAM density achieved by the
24 unique chip designs on the wafer.space Run 1 reticle. The reticle is
30mm x 24mm and contains 37 slot placements (some designs appear more
than once for redundancy).

All designs were fabricated on GlobalFoundries' GF180MCU process, a
180-nanometer (0.18um) technology node. This is a mature, relatively
large-geometry process — for comparison, modern smartphone chips use
3nm or 5nm processes with features roughly 50x smaller.


WHAT ARE STANDARD CELLS?
========================

A "standard cell" is a pre-designed, pre-verified building block used to
construct digital circuits. Think of them like LEGO bricks for chip
design: each cell performs one simple logic function (an AND gate, a
flip-flop for storing one bit, a buffer for boosting signal strength),
and a chip designer assembles thousands or millions of them to build
complex circuits.

Standard cells in a library all share the same height (so they line up
in rows) but vary in width depending on their function. A simple
inverter might be 3um wide, while a flip-flop (which stores data) might
be 17um wide. Automated tools place these cells in rows and then route
wires between them.

The "density" of standard cells — how many fit per square millimeter —
is a key measure of how efficiently a design uses its silicon area.
Higher density generally means more logic functionality packed into less
chip area, which reduces cost.


STANDARD CELL LIBRARIES ON THIS RETICLE
========================================

The GF180MCU process offers two standard cell libraries, differing in
their "track count" — essentially how tall each row of cells is:

  Library             Row Height    Rows per mm    Relative Density
  ─────────────────────────────────────────────────────────────────
  mcu7t5v0 (7-track)    4.78 um       209 rows         100% (base)
  mcu9t5v0 (9-track)    5.94 um       168 rows          80%

The 7-track library packs rows 24% closer together, giving
proportionally higher density. However, the taller 9-track cells
provide more space for internal wiring, which can make it easier for
automated routing tools to complete complex designs without congestion.

Both libraries use the same "5v0" process variant (5-volt tolerant I/O
with 3.3V core logic). There are no separate 3.3V-only or 5V-only
standard cell libraries on this reticle — all designs use the same
5V-tolerant cells. [1]

Most designs chose one library exclusively. Notable exceptions include
Tiny Tapeout (TTPG/TTP2), where each of the 52 sub-projects
independently chose their library, and BRWN and JKU2, which mix both
libraries within a single design. [2]


THEORETICAL MAXIMUM STANDARD CELL DENSITY
==========================================

If you filled an entire square millimeter with nothing but one type of
standard cell (no wiring space, no gaps), the theoretical maximum
density would be:

  Cell Type             7-track max    9-track max    What it does
  ─────────────────────────────────────────────────────────────────
  Inverter (inv_1)         67k/mm²        54k/mm²    Flips a signal
  NAND gate (nand2_1)      57k/mm²        46k/mm²    Basic logic gate
  Buffer (buf_1)           50k/mm²        40k/mm²    Strengthens a signal
  AND3 gate (and3_1)       32k/mm²        26k/mm²    3-input logic gate
  Flip-flop (dffq_1)      12k/mm²        10k/mm²    Stores one bit

These are hard upper bounds. [3] In practice, real designs achieve
significantly less because:

  (a) Routing overhead — wires connecting cells consume ~30-50% of area
  (b) Mixed cell types — designs use a mix of small and large cells
  (c) Filler cells — gaps between logic cells must be filled
  (d) Power planning — power/ground rails consume area
  (e) Clock distribution — clock tree buffers and wiring take space

A well-optimized design typically achieves 40-70% of the theoretical
maximum for its dominant cell type. [4]

7-TRACK vs 9-TRACK LIBRARY COMPARISON
=======================================

Comparing designs that exclusively use one library:

                              7-track (mcu7t5v0)    9-track (mcu9t5v0)
  ────────────────────────────────────────────────────────────────────
  Designs using this lib:     14                    10
  Best core density:          55k SC/mm² (2975)     39k SC/mm² (CHES)
  Best peak grid cell:        74k SC/mm² (2975)     45k SC/mm² (KIAN)
  Median core density:        24k SC/mm²            20k SC/mm²

The 7-track library achieves roughly 20-40% higher density in practice,
consistent with its 24% theoretical advantage from shorter row
height. [32] The 9-track library's best result (CHES at 39k SC/mm²)
falls between the 7-track library's median and best, suggesting that
good design practices matter at least as much as library choice.


SRAM BLOCK USAGE
=================

SRAM (Static Random-Access Memory) blocks are pre-designed memory
macros provided by the foundry. Unlike standard cells, which are
composed by automated tools, SRAM blocks are hand-optimized fixed-size
units designed to store data as densely as possible.

SRAM vs STANDARD CELL TRANSISTOR DENSITY
==========================================

A critical comparison: how does the transistor density inside a foundry-
provided SRAM block compare to the density achieved by packing standard
cells?

"Transistor density" here counts the number of distinct regions where a
gate electrode (polysilicon) crosses an active area (diffusion) — each
such crossing forms one transistor. [37]

  SRAM macros (foundry-provided, hand-optimized): [38]

    Macro                  Size          Trans/mm²
    ────────────────────────────────────────────────
    sram1024x8 (OCD)     301 x 516 um     385k/mm²    Densest SRAM
    sram512x8 (OCD)      301 x 322 um     332k/mm²
    sram256x8 (OCD)      301 x 225 um     270k/mm²
    sram512x8 (standard) 432 x 485 um     154k/mm²    Most commonly used
    sram256x8 (standard) 432 x 341 um     124k/mm²
    sram128x8            432 x 269 um      98k/mm²
    sram64x8             432 x 233 um      79k/mm²

  Best standard cell regions (automated place-and-route): [39]

    Design     Peak 1mm² Trans/mm²   Library
    ────────────────────────────────────────────────
    MOLE           305k/mm²          7-track
    TTPG           297k/mm²          mixed
    CAFE           296k/mm²          7-track
    2975           292k/mm²          7-track
    JKU1           258k/mm²          7-track
    TQVC           252k/mm²          7-track
    CHES           234k/mm²          9-track

  Comparison:

    The standard SRAM macros (154k/mm²) achieve comparable or even
    LOWER transistor density than the best standard cell regions
    (250k-305k/mm²). This is surprising — SRAM is typically considered
    the densest structure on a chip.

    The explanation: the standard SRAM macros (gf180mcu_fd_ip_sram) have
    large peripheral circuits (address decoders, sense amplifiers, I/O)
    that dilute the density of the compact bitcell array. The actual
    6-transistor SRAM bitcells in the core are extremely dense, but the
    overhead of the surrounding circuitry brings the overall macro
    density down. [40]

    The OCD (OpenRAM Characterization Design) SRAM variants achieve
    270k-385k/mm², approaching or exceeding peak stdcell density. These
    appear to be more compact macro designs with less peripheral
    overhead. [41]

    For whole-chip averages, SRAM-heavy designs like BTAP (56 blocks,
    153k trans/mm² core) achieve lower overall transistor density than
    pure stdcell designs like 2975 (253k trans/mm² core), because the
    SRAM peripherals and inter-block spacing waste area. [42]


KEY FINDINGS
=============

1. The densest standard cell design (2975) achieves 55k SC/mm² averaged
   over its core, with a peak of 74k SC/mm² in its densest region.
   This approaches the theoretical packing limit for the cell mix it
   uses. [6][30]

2. The 7-track library (mcu7t5v0) consistently achieves ~20-40% higher
   density than the 9-track library (mcu9t5v0), closely matching the
   24% theoretical advantage from its shorter row height. [32]

3. Standard cell transistor density (up to 305k/mm²) can exceed that of
   the commonly-used foundry SRAM macros (154k/mm²), because SRAM
   peripheral circuits dilute the density of the compact bitcell
   array. [38][39][40]

4. Designs span a 30x range in stdcell density (2k to 55k SC/mm²
   core average), reflecting fundamentally different design types —
   from dense digital SoCs to sparse analog test structures. [6][28]

5. Within a single design, stdcell density typically varies 4-12x
   between the densest core region and the sparsest edge, driven
   primarily by the I/O pad ring consuming die perimeter. [43]

[43] Within-die density variation measured across 1mm x 1mm grid cells
